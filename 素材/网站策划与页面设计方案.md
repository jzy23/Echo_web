# 吉林省睿语智软科技有限公司网站策划与页面设计方案

> 当前阶段：信息架构、页面布局与视觉方向。本文档不包含网站代码。

## 1. 网站定位

网站不做“多产品集合型官网”，而以 **EchoSim 车辆仿真软件** 为唯一核心产品，集中表达以下价值：

- 面向乘用车、商用车、特种车辆的整车与底盘动力学仿真。
- 从车辆建模、动力学求解、场景测试到控制器联调和结果分析的完整流程。
- 支持 ADAMS、Simulink、CarSim、TruckSim、VTD 等工程工具的模型迁移、联合仿真或流程协同。
- 以真实软件界面、仿真视频和验证曲线建立工程可信度。

推荐主定位语：

**EchoSim 车辆仿真平台**  
**让模型驱动车辆研发**

辅助表达：

**统一建模 · 动力学仿真 · 场景测试 · 闭环验证**

## 2. 目标访问者与网站任务

| 访问者 | 最关心的问题 | 网站应促成的动作 |
|---|---|---|
| 整车厂、零部件企业研发人员 | 能否覆盖实际车型、工况和控制算法验证 | 查看能力与案例，申请演示 |
| 高校及科研院所 | 是否便于建模、教学、科研和二次开发 | 查看软件界面、模型案例与技术资料 |
| 商用车、特种车辆项目负责人 | 能否解决特定车辆和复杂工况问题 | 提交项目需求，联系技术团队 |
| 决策者与采购人员 | 国产自主、工程成熟度、替代成本 | 了解公司、验证证据与交付方式 |

网站的核心转化目标不是“立即购买”，而是：**观看仿真演示 → 理解技术能力 → 提交车辆研发问题或预约产品演示**。

## 4. 首页布局设计

首页承担完整的品牌叙事，建议控制在 7 个主要区块。

### 4.1 顶部导航

- 高度约 72px，深海军蓝背景，滚动后保持吸顶。
- 左侧使用 ECHOSIM 主标识；公司全称放在页尾和“关于我们”页，不挤占导航。
- 中部为导航菜单；右侧“联系咨询”为描边按钮。
- 当前页面用一条短红线标识，延续宣传册中的红色视觉记忆。

### 4.2 首屏 Hero

左侧文案：

- Eyebrow：`VEHICLE SIMULATION PLATFORM`
- 主标题：`EchoSim 车辆仿真平台`
- 品牌句：`让模型驱动车辆研发`
- 辅助说明：`覆盖车辆建模、动力学仿真、场景测试与闭环验证，为整车、底盘及控制系统研发提供统一的工程仿真环境。`
- 主按钮：`了解 EchoSim`
- 次按钮：`观看仿真演示`

右侧视觉：

- 使用半透明整车/底盘模型作为主体。
- 背后叠加真实 EchoSim 软件界面、车辆工况画面和小型验证曲线。
- 不使用人形机器人作为首屏对象。
- 首屏背景可从“车型对比分析.mp4”或车辆仿真画面中提取静态关键帧；桌面端可使用静音短循环视频，移动端使用静态封面。

### 4.3 从车辆模型到闭环验证

五步横向流程：

1. 车辆建模
2. 动力学求解
3. 场景与工况
4. 控制器联调
5. 数据分析

每一步只保留一行价值说明，通过线性箭头串联。该区块回答“EchoSim 如何进入研发流程”，不罗列全部功能。

### 4.4 EchoSim 核心能力

深色背景上的四张能力卡，不再使用多个产品名称作为并列分类：

| 能力模块 | 主要内容 | 建议素材 |
|---|---|---|
| 整车与底盘动力学 | 整车、悬架、转向、制动、轮胎、动力传动 | `宣传版面/10.jpg`、车辆底盘界面 |
| 高可靠车辆模型库 | 参数化车型、部件配置、模板复用、一致性检查 | `宣传手册/4.jpg` |
| 联合仿真与开放接口 | ADAMS / Simulink / CarSim / TruckSim / VTD，API / FMU / CSV 等 | `宣传版面/7.jpg`、`宣传版面/10.jpg` |
| MIL / SIL / HIL 验证 | 控制器联调、数据记录、回放、分析与工程验证 | `宣传版面/3.jpg`、`宣传手册/6.jpg` |

卡片点击后进入“核心能力”对应章节，而不是跳转到不同产品。

### 4.5 面向车辆研发的应用场景

四张横向图像卡：

- 乘用车研发：操稳、平顺性、制动、耐久等。
- 商用车研发：卡车、客车及商用车型的整车与底盘仿真。
- 特种车辆研发：复杂地形、履带车辆和特殊工况。
- ADAS 与控制策略：感知/规划/控制算法的联合与闭环验证。

本区块采用明亮背景，避免整个页面长期处于深蓝色，增加阅读节奏。

### 4.6 案例演示

主标题：`看见运动，也看清系统关系`

- 主推荐视频：`车型对比分析.mp4`
- 次级视频：`履带车动力学仿真.mp4`、`地外车动力学仿真.mp4`
- `具身机器人动力学仿真.mp4` 放入“更多多体动力学案例”，不作为首页第一屏案例。
- 视频默认不自动播放声音；点击后在页面内弹层播放。
- 每个视频卡片显示：对象、验证目标、仿真类型，不只显示文件名。

### 4.7 技术证据与工程可信度

标题：`精度、效率与工程可用性`

建议采用“左侧真实软件界面 + 右侧验证证据”的版式：

- ADAMS 文件导入与模型求解流程。
- 对比曲线和结果一致性说明。
- OVD 求解器的技术路线说明。
- 工程接口、模型复用和批量分析能力。

这里应尽量使用真实界面和真实曲线，少用装饰性 3D 图。

## 5. 内页设计

### 5.1 EchoSim 产品页

页面目标是回答“这是什么、能做什么、如何工作”。

布局顺序：产品首屏 → 五步流程 → 软件界面导览 → 核心能力矩阵 → 支持的联合工具/接口 → 演示视频 → 咨询 CTA。

产品页中的软件截图应增加局部放大和功能标注，使非软件使用者也能看懂，而不是直接贴完整截图。

### 5.2 核心能力页

采用左侧吸顶目录、右侧长内容的技术页结构。每项能力包含：

1. 研发问题
2. EchoSim 的处理方式
3. 软件界面或模型示例
4. 输出结果
5. 相关案例

该页面可承载较强的工程细节，是技术人员判断产品是否适用的关键页面。

### 5.3 应用场景页

每类车辆使用统一模板：行业问题 → 仿真对象 → 典型工况 → 可分析指标 → 示例视频/截图 → 联系技术团队。

首页只出现四张入口卡，详细内容放入对应场景页，避免首页变成展板式信息堆叠。

### 5.4 案例演示页

顶部按车型和验证目标筛选：

- 车型：乘用车 / 商用车 / 特种车辆 / 其他
- 目标：动力学 / 控制 / 场景 / 联合仿真 / HIL

案例卡片建议使用 16:9 封面，进入详情后展示“任务—模型—工况—结果”。四段现有视频可以直接形成第一版案例库。

### 5.5 技术支持页

第一期重点使用 `ADAMS文件的导入和求解` 中的 6 张图，形成一篇完整的技术文章或操作说明。结构为：导入 → 模型检查 → 求解设置 → 运行 → 结果对比 → 结论。

后续可扩展软件下载、版本说明、常见问题、学习资料，但当前资料不足时不建议先放空栏目。

### 5.6 关于我们页

以公司定位、研发方向、核心技术与联系方式为主。暂不虚构客户 Logo、专家团队、融资信息、奖项或发展时间线。

## 6. 视觉系统

### 色彩

| 用途 | 色值 |
|---|---|
| 主背景深蓝 | `#071A33` |
| 深色卡片 | `#0B2B50` |
| 品牌蓝 | `#1457C8` |
| 技术高亮青 | `#23B7E5` |
| 页面浅底 | `#F5F8FB` |
| 分隔线 | `#DCE5EF` |
| 标题深色 | `#0D223A` |
| 小面积强调红 | `#FF3B30` |

红色只用于当前导航、编号、关键提示，不用于大面积背景。

### 字体与版式

- 中文：思源黑体或 HarmonyOS Sans SC。
- 英文与数字：Inter 或 DIN 风格字体。
- 桌面内容最大宽度：1200–1280px，12 栏栅格，栏间距 24px。
- 移动端左右留白：20px；卡片全部改为单列或横向滑动。
- 一级标题强调短句，不直接把宣传册的大段文字搬到网页。

### 图片风格

- 核心证据优先级：真实软件界面 > 仿真结果 > 车辆/底盘工程渲染 > 装饰性科技背景。
- 宣传展板可作为信息来源和局部素材，不建议整张嵌入网页。
- 同一区块只使用一种图像语言，避免真实截图、AI 渲染和图标混杂。

### 动效

- 首屏：轻微模型视差或短循环仿真视频。
- 流程区：进入视口后依次点亮五个步骤。
- 能力卡：悬停只做 4–6px 上浮和边框高亮。
- 曲线图：缓慢绘制一次，不循环闪动。
- 尊重系统“减少动态效果”设置。

## 7. 移动端布局原则

- 首屏图像放到文案下方，按钮保持并排或上下两行。
- 五步流程改为纵向时间轴。
- 四张能力卡改为单列，保留标题、摘要和一张证据图。
- 视频卡片采用 16:9，全屏播放。
- 顶部导航收为菜单，固定保留“咨询”按钮。
- 不在移动端自动播放背景视频，减少流量与功耗。

## 9. 上线前必须确认的内容

以下宣传数据已经出现在现有材料中，但建议在正式网站使用前由公司确认来源和统计口径：

- `10+` 自主软件产品、`500+` 车型模型、`1000+ km` 道路与场景库、`100+` 服务客户、`10+` 年工程经验。
- 仿真效率提升 `2–5 倍`、成本降低 `60%+`、关键指标误差 `≤1%`。
- “精度基本一致，仿真快 15%”及 OVD 求解器与 ADAMS 对比结论。
- 与 ADAMS、Simulink、CarSim、TruckSim、VTD 的具体兼容、导入、联合仿真或替代关系。
- 第三方品牌名称和 Logo 在公开网站上的使用授权与表述方式。

在确认前，页面使用“高精度”“高效率”“支持模型导入/工具协同”等定性语言，不直接展示未经核验的数字结论。

## 10. 本轮设计结论

推荐的网站不是把宣传册网页化，而是形成一条清晰叙事：

**EchoSim 是什么 → 如何进入车辆研发流程 → 能解决哪些车辆仿真问题 → 有哪些真实演示与技术证据 → 如何联系技术团队。**
